Module 01

Online Invoice & Payment System

This module builds an end-to-end invoicing system: you create invoices in an admin view, clients receive a link to a payment page, they pay with a credit card, and you get an email confirmation. No third-party invoicing app, no monthly subscription. Just your website, Netlify Functions for the backend, and Stripe for payment processing.

How the payment flow works
You open the admin view and create an invoice: client name, service description, and amount. The invoice is saved to your database with a unique ID and a status of "unpaid."
You copy the invoice link (e.g., yourdomain.com/invoice.html?id=INV-1042) and send it to the client by email or text.
The client opens the link, sees their invoice with the amount due, and clicks "Pay Now." Your frontend calls a Netlify Function to create a Stripe Payment Intent.
Stripe handles the card input securely (via Stripe Elements). No card data ever touches your servers. Stripe processes the payment.
On success, your Netlify confirmation function marks the invoice as paid in Supabase and sends you a notification email via Resend. The client sees a success screen.
The entire invoicing system was designed and written by AI. The HTML invoice page, all three Netlify Functions, the Stripe integration, and the database schema were all generated through conversation with Claude. A bug was also caught during testing - a price calculation function was referencing the wrong dropdown element. Running a code review pass with AI ("review this JavaScript function for bugs, especially in how it reads the form values") identified the error before it could affect real payments.
Netlify Functions - Your backend

Netlify Functions are small Node.js scripts that run on Netlify's servers when called by your frontend. They're the right place for any code that uses secret API keys - Stripe's secret key, Supabase's service role key, your email API key. The frontend calls the function URL, the function runs securely, and returns a response.

Create a netlify/functions/ folder in your project root. Every .js file in this folder becomes an API endpoint automatically at /.netlify/functions/filename.
Use native Node.js fetch() for all HTTP calls. Avoid npm packages where possible - they add complexity and occasional build failures. Everything needed here (Stripe API, Supabase REST API, Resend API) can be called with plain fetch.
Access your secret environment variables inside functions with process.env.YOUR_VARIABLE_NAME. Set them in Netlify under Site settings → Environment variables → Add a variable.

You'll need three functions for the payment system:

The create-payment-intent function
// netlify/functions/create-payment-intent.js exports.handler = async (event) => { // Only allow POST requests if (event.httpMethod !== 'POST') { return { statusCode: 405, body: 'Method Not Allowed' }; } let amount, invoiceId; try { ({ amount, invoiceId } = JSON.parse(event.body)); } catch { return { statusCode: 400, body: 'Invalid request body' }; } // amount comes in as dollars; Stripe uses cents const amountCents = Math.round(parseFloat(amount) * 100); if (isNaN(amountCents) || amountCents <= 0) { return { statusCode: 400, body: 'Invalid amount' }; } const response = await fetch('https://api.stripe.com/v1/payment_intents', { method: 'POST', headers: { 'Authorization': `Bearer ${process.env.STRIPE_SECRET_KEY}`, 'Content-Type': 'application/x-www-form-urlencoded' }, body: new URLSearchParams({ amount: String(amountCents), currency: 'usd', 'metadata[invoice_id]': invoiceId }) }); const intent = await response.json(); if (intent.error) { return { statusCode: 500, body: JSON.stringify({ error: intent.error.message }) }; } return { statusCode: 200, headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ clientSecret: intent.client_secret }) }; };
Common Issues
Function returns 500 with "No such api_key"
Your STRIPE_SECRET_KEY environment variable isn't set in Netlify, or was set incorrectly. Go to Netlify → Site configuration → Environment variables. The value should start with sk_test_ (test mode) or sk_live_ (live mode). Make sure there are no leading/trailing spaces - they're invisible but will cause authentication failures.
Function works in Netlify's test dashboard but fails when called from the website
CORS (Cross-Origin Resource Sharing) is blocking the request. Your Netlify Function needs to return CORS headers. Add to the return object: headers: { 'Content-Type': 'application/json', 'Access-Control-Allow-Origin': '*', 'Access-Control-Allow-Headers': 'Content-Type' }. Also add a handler for OPTIONS preflight requests at the top of the function.
Amount arrives at Stripe as $0.01 instead of $125.00
Stripe amounts are in the smallest currency unit (cents for USD). $125 must be sent as 12500, not 125 or 1.25. The bug often comes from the HTML form: verify the amount value being sent from the frontend is in dollars (the number the user sees), and that you're multiplying by 100 and rounding before sending to Stripe.
Stripe setup
Create a free Stripe account at stripe.com. Complete identity verification (required for receiving payouts to your bank).
In the Stripe dashboard, make sure the mode toggle in the top-left shows "Test" while you're building. You'll switch to live when deploying. Go to Developers → API keys and copy your test publishable key (pk_test_...) and secret key (sk_test_...).
Add the secret key to Netlify environment variables as STRIPE_SECRET_KEY.
Add Stripe.js to your invoice HTML page. This must load from Stripe's servers - do not download and self-host it:
<script src="https://js.stripe.com/v3/"></script>
Initialize Stripe in your page script with the publishable key (this one is safe for frontend use): const stripe = Stripe('pk_test_your_key_here');
Use Stripe Elements for the card input. This renders a secure, hosted card form inside an iframe - no card data ever passes through your code:
const elements = stripe.elements(); const cardElement = elements.create('card'); cardElement.mount('#card-element'); // mounts into <div id="card-element"></div>
Use test card number 4242 4242 4242 4242 with any future expiry and any 3-digit CVC to test payments in test mode. Stripe has a full list of test cards for different scenarios (declined, insufficient funds, etc.) in their docs.
Your Stripe secret key (sk_live_...) must never appear in any file that gets committed to GitHub or served to a browser. Store it only as a Netlify environment variable. The publishable key (pk_live_...) is designed to be public and can be in your HTML. The secret key is not. If you accidentally expose your live secret key, go to Stripe → Developers → API keys → Roll key immediately.
Module 02

Automated Email Notifications

Every time a client pays an invoice, you receive an automatic email with the details - client name, amount, invoice ID, and timestamp. This module covers setting up Resend (a free transactional email API), verifying your sending domain, and wiring the notification into your payment confirmation function.

Why Resend, and what the alternatives are

Resend is a developer-focused email API with a free tier of 3,000 emails per month and 100 per day. It supports sending from your own domain, which means emails come from hello@yourbusiness.com rather than a generic service address - significantly better for deliverability and professionalism.

Alternatives worth knowing about: SendGrid (larger scale, slightly more complex setup), Postmark (excellent deliverability, focused on transactional email), Mailgun (popular with developers). For this use case - a small volume of payment notification emails - Resend is the simplest choice.

Verifying your sending domain

To send email from your own domain address, you must prove to email servers worldwide that you're authorized to send from it. This is done via DNS records. Without this, your emails will go to spam or be rejected outright.

Create a Resend account at resend.com. Go to Domains → Add Domain and enter your domain name (e.g., yourbusiness.com).
Resend provides 3 DNS records to add. These are:
  • SPF - A TXT record that lists Resend as an authorized sender for your domain
  • DKIM - A TXT record with a cryptographic key that signs your outgoing emails, proving they're legitimate
  • DMARC - A TXT record that tells receiving servers what to do with emails that fail SPF or DKIM (reject, quarantine, or just report)
Log into your domain registrar (where you bought your domain - GoDaddy, Namecheap, Squarespace, Google Domains, etc.) and navigate to DNS settings. Add each record exactly as provided by Resend. The record type, name, and value must be exact.
Click "Verify" in Resend. DNS changes propagate globally over time - typically 15 minutes to a few hours, but can occasionally take up to 24-48 hours in edge cases.
Create an API key: Resend → API Keys → Create API Key. Copy it and add it to Netlify environment variables as RESEND_API_KEY. Also add your email address as OWNER_EMAIL.
Common Issues
Resend says "DNS records not verified" after 24 hours
One or more records wasn't entered correctly. Common mistake: the DKIM record name should be something like resend._domainkey - some registrars automatically append your domain to the name, resulting in resend._domainkey.yourdomain.com.yourdomain.com. If your registrar auto-appends the domain, enter just resend._domainkey without your domain. Check each record using a tool like mxtoolbox.com.
Emails send successfully but end up in spam
Most commonly caused by DMARC not being set up, or the DMARC policy being set to none (just monitoring). Make sure all three records (SPF, DKIM, DMARC) are verified in Resend. Also check that your email subject lines don't look like spam (avoid ALL CAPS, excessive punctuation, or words like FREE, URGENT, ACT NOW).
Resend returns 403 Forbidden when called from Netlify Function
The API key is wrong, not set in Netlify environment variables, or the variable name doesn't match what you're using in code (process.env.RESEND_API_KEY). Environment variables in Netlify require a redeploy to take effect - if you added the variable after the last deploy, trigger a new deploy.
AI explained the DNS records setup. SPF, DKIM, and DMARC are not intuitive concepts for non-developers. When asked "what exactly is a DKIM record and why does it need to be on my domain?", AI gave a plain-English explanation (private/public key cryptography applied to email authentication) that made the setup process understandable rather than a blind copy-paste exercise.
Sending the notification email

This code lives inside your confirm-payment.js Netlify Function, called after Stripe confirms payment success:

// Inside confirm-payment.js - call this after marking invoice as paid async function sendPaymentNotification(invoiceId, clientName, amount) { const response = await fetch('https://api.resend.com/emails', { method: 'POST', headers: { 'Authorization': `Bearer ${process.env.RESEND_API_KEY}`, 'Content-Type': 'application/json' }, body: JSON.stringify({ from: `Your Business <hello@yourdomain.com>`, to: process.env.OWNER_EMAIL, subject: `Payment received - ${clientName} - $${amount}`, html: ` <div style="font-family: sans-serif; max-width: 560px; margin: 0 auto;"> <h2 style="color: #2a5c45;"> Payment Received</h2> <table style="width: 100%; border-collapse: collapse;"> <tr><td style="padding: 8px 0; color: #555;">Invoice</td> <td style="padding: 8px 0; font-weight: bold;">${invoiceId}</td></tr> <tr><td style="padding: 8px 0; color: #555;">Client</td> <td style="padding: 8px 0;">${clientName}</td></tr> <tr><td style="padding: 8px 0; color: #555;">Amount</td> <td style="padding: 8px 0; font-weight: bold; color: #2a5c45;">$${amount}</td></tr> <tr><td style="padding: 8px 0; color: #555;">Paid at</td> <td style="padding: 8px 0;">${new Date().toLocaleString()}</td></tr> </table> </div> ` }) }); if (!response.ok) { console.error('Email failed:', await response.text()); } }
